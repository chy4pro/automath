**LIVE CLAIM — Exact checker contracts retained for later use.** These are specifications, not executed certificates or benchmark measurements. No external packages or mathematical search are required to check a supplied object.

- MOLS: JSON `{n:22, squares:[...]}` with exactly k arrays of 22 rows, each of length 22. Reject nonintegers or symbols outside 0…21. For every row and column require 22 distinct symbols. For each unordered pair of squares, clear a 484-entry boolean array and mark `22*a+b` at all 484 cells; reject repetitions. A four-square success certifies N(22)≥4 only. Existing Sage QDM data must first be developed and checked by an independent implementation; its source doctest is not a replay performed here.
- Degree–diameter: JSON with `n` and n adjacency arrays. Require integer labels 0…n−1, no loops/duplicates, reciprocal edges, and degree at most the requested Δ. For each root perform queue-based BFS, requiring every vertex to be reached within D steps. Checking only one root is insufficient unless vertex transitivity is separately certified; no symmetry assumption is made here.
- Cage: same format, with degree exactly 3 and connectedness. For each undirected edge uv, temporarily omit uv and BFS from u to v. The minimum of these path lengths plus one is the girth. Require girth exactly 13 for n(3,13). This avoids trusting a claimed automorphism group or a numerical eigenvalue test.
- Kissing witness: JSON dimension 11 and N vectors, each coordinate an integer pair `(p,q)` representing p+q√2. Use arbitrary-precision integers. Accumulate every squared norm as a pair, requiring (36,0); accumulate each distinct-pair inner product and compare to (18,0). Determine the sign of a+b√2 from signs of a,b, comparing a² with 2b² only in the opposite-sign cases. Reject duplicates automatically through the pair test. Input bit lengths must be recorded; the runtime estimate is for the small integer coefficients of the located format, not arbitrary enormous inputs or general real coordinates.
