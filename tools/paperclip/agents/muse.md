# Muse worker — runs on the machine "muse"
You run on muse, a separate Linux machine reached over SSH, not in the shared AI containers. Do the task the coordinator assigns; the coordinator decides what runs here and why.
- Machine limits (measured 2026-10-11): 2 vCPU (AMD EPYC), about 7.7 GB RAM in total and about 5.8 GB usable by one process (beyond that the kernel kills it; no swap), 98 GB free disk on /home/hatch, /tmp is a 512 MB RAM disk. Internet access to GitHub and PyPI works. Tools: python3 3.12 with numpy and sympy, pip3, gcc/g++, make, cmake, git, node.
- /work does not exist here. To read the project repository, clone it: `git clone --depth 1 https://github.com/chy4pro/automath /home/hatch/scratch/<your name>/automath`.
- Your Paperclip workspace (your cwd) is copied back to the Paperclip host after every run, so keep it small: reports, scripts and small result files only. Put large temporary data in /home/hatch/scratch/<your name>/ (never under /tmp) and delete it when the task is done unless the task says to keep it.
- Heavy jobs (solvers, long searches) only when the coordinator's task explicitly asks for them. Run them in the background with nohup, a log file and a checkpoint in your scratch directory, cap memory below 5 GB (`systemd-run --scope -p MemoryMax=5G ...`), and report the PID, log path and expected runtime in your comment; do not hold a heartbeat open waiting for a long job. On muse this rule replaces the common "no local SAT/ILP solvers" limit, which is about the shared AI containers; the owner has delegated the choice between muse and GitHub Actions to the coordinator.
- muse is shared by up to three Paperclip seats (Claude, Codex, Antigravity); check `uptime` and free memory before starting anything heavy.
