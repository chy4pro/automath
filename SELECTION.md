# SELECTION GATE v2 (v5 architecture) — the highest-leverage decision in the system
With ≤2 deep lines, one selection error costs a week of the scarcest resource.
Selection gets Fable-grade attention and is re-validated continuously, not ritually.

## The question (sign flipped from v1)
NOT "which candidate survives an audit?" but:
> **"What is the most valuable problem we can attack for one week, given what the free
> layer can carry and what the case library says AI is currently cracking?"**
Six rounds / zero GO means the gate is broken, not that the pool is empty.

## Inputs (all cheap/free)
1. Pool: orchestration/TARGETS.md rows + prospecting archives (31/31 MSC areas swept once;
   re-sweep stale areas on demand).
2. Cheap probes FIRST: any probe ≤ a few CPU-hours that materially updates solvability
   (e.g., the Agrawal A-1 probe, ≤4 CPU·h) runs BEFORE judgment. Engine probes are free.
3. Case-library priors: what class is falling to AI right now (construction-type: YTD, S^6;
   analytic advances: RH). Same-class targets get upgraded priors. notes/case_intel/.
   **Prior sharpened 2026-08-24 (August evidence: YTD disproof, Alpoge S^6 construction claim,
   Brendle-Hung S^2xS^2 metric, Jacobian counterexample, Caratheodory/Loewner claims — ALL are
   constructions/counterexamples): prefer targets whose ultimate proposition admits, in at least
   one direction, an explicit witness checkable by a FINITE machine-verifiable certificate.**
4. **Race clock (2026-08-24):** famous targets are now closed days apart by expert+AI operators
   (Alpoge lost Hopf-curvature to Brendle by ~days holding a candidate construction). Crowding
   checks must include X/self-hosted channels, not just arXiv/gh; and a running line that gets
   within reach of closure SPRINTS to the certificate before any polishing.
4. Openness verification: web scout + MANDATORY structured checks (arXiv API, gh incl.
   unmerged PRs, OEIS); trap lesson: repo-merged resolutions are invisible to search.

## Value criteria (owner's 08-16 doctrine, unchanged)
Named/famous first; ultimate-proposition only (no boundary-pushing projects); believe AI
capability; verification discipline scales with fame. Score = expected significance ×
P(solvable in ~a week of deep attack) — judged, not formula-worshipped (no Goodhart).

## S-5 asset discipline (kept from v4 — it caught two ghost assets)
Any claimed "we have an edge/asset" must name a file path and a measurable minimal check
with its result, else it scores zero.

## Continuation gate (new, from the audit)
Every ~10 rounds (or weekly), a running line faces the SAME question as a new candidate:
"is continuing this line still the most valuable use of the slot?" Sunk cost is not an
argument. Closing with a consolidated writeup is a valid, honorable outcome.

## FAMOUS-WATCH shelf (2026-08-24, from the S^6 lesson)
Discovery was never the gap: S^6 sat in notes/fc_catalog.md (Mathoverflow/1973) from day one
and was triaged into oblivion. The gap: a famous target judged "no route known" gets dropped
and never resurfaces, while the capability frontier moves WEEKLY (case library keeps proving
our solvability priors lag reality). Rule: a named/famous ultimate-proposition target that
fails ONLY on P(solvable-this-week) is never DROPPED — it is SHELVED to
notes/selection/famous_watch.md, each row recording its UNLOCK CONDITION: what new
tool/scaffold/precedent would make it attackable. Trigger: every new case-library entry is
matched against shelf unlock conditions (a new case = a new public scaffold); matches are
re-scored at the next selection task. Selection tasks MUST read the shelf alongside the pool.

## Procedure (bounded Fable task, spawned by dialogue when a slot opens)
1. Refresh pool head (probes + openness checks on top ~10). 2. Pick with a one-page
rationale citing evidence paths. 3. Write lines/<line>/BOOTSTRAP.md for the new line.
4. Report the pick + rationale to the user via dialogue (visibility; selection authority
is delegated per owner ruling 08-22).
